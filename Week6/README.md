# LLM Baseline Evaluation (Release v0.1)

A small evaluation harness that runs a golden set of 30 questions about LLM fundamentals (tokenization, embeddings, decoding, positional encoding, API cost and limits) against a local Ollama model. Each answer is scored by keyword coverage, and the results are saved to a CSV file to serve as a baseline for later releases.

## Project Structure

```
.
├── main.py                # Runs the baseline evaluation
├── golden_set.json        # 30 questions with expected answers, keywords and sources
├── baseline_results.csv   # Output generated by main.py
└── requirements.txt       # Python dependencies
```

## Requirements

- Python 3.9 or later
- [Ollama](https://ollama.com/) installed and running locally
- The `llama3.2` model pulled in Ollama

## Setup

1. Install the dependency:

   ```bash
   pip install -r requirements.txt
   ```

2. Pull the model and make sure Ollama is running:

   ```bash
   ollama pull llama3.2
   ollama serve
   ```

   Ollama listens on `http://localhost:11434` by default. If it is already running as a background service, you do not need to run `ollama serve`.

## Usage

```bash
python main.py
```

The script loads `golden_set.json`, sends each question to the model, scores the answer, prints the details to the console and writes `baseline_results.csv`.

## How It Works

1. **Load the golden set.** Questions are read from `golden_set.json`.
2. **Query the model.** Each question is sent to Ollama's `/api/generate` endpoint with `temperature` set to `0` for reproducible output and a 120 second timeout.
3. **Score the answer.** Keyword coverage is calculated as:

   ```
   score = (matched keywords / total keywords) x 100
   ```

   Matching is a case-insensitive substring check against the model's answer.
4. **Assign a status.**

   | Status   | Meaning                                  |
   |----------|------------------------------------------|
   | `PASS`   | Score is 60% or higher                   |
   | `REVIEW` | Score is below 60%, needs manual review  |
   | `ERROR`  | The request failed (score recorded as 0) |

5. **Save and summarize.** Results are written to CSV and a summary is printed.

## Golden Set Format

Each entry in `golden_set.json` has the following fields:

| Field             | Description                                      |
|-------------------|--------------------------------------------------|
| `id`              | Unique question ID (Q001 to Q030)                |
| `question`        | The question sent to the model                   |
| `expected_answer` | Reference answer used for manual comparison      |
| `keywords`        | Terms expected in a good answer, used for scoring |
| `source`          | Documentation or paper the answer is based on    |

The questions cover these topics:

- **Tokenization (Q001 to Q008):** tokens, BPE, WordPiece, SentencePiece, token ratio
- **API usage and cost (Q009 to Q014):** input and output tokens, cost, context window, rate limits, monitoring
- **Generation (Q015 to Q022):** autoregressive generation, next-token prediction, greedy decoding, sampling, temperature, top-k, top-p
- **Embeddings and positions (Q023 to Q029):** embeddings, token IDs, positional encoding, sinusoidal encoding, RoPE
- **Architecture (Q030):** the Transformer's role in an autoregressive model

## Output Format

`baseline_results.csv` is UTF-8 with a BOM, so it opens correctly in Excel. It has one row per question and these columns:

`Question_ID`, `Question`, `Expected_Answer`, `LLM_Answer`, `Matched_Keywords`, `Missing_Keywords`, `Score`, `Status`, `Source`, `Model`, `Release`

## Configuration

Settings are defined at the top of `main.py`:

| Variable      | Default                                | Purpose                      |
|---------------|----------------------------------------|------------------------------|
| `OLLAMA_URL`  | `http://localhost:11434/api/generate`  | Ollama endpoint              |
| `MODEL_NAME`  | `llama3.2`                             | Model being evaluated        |
| `INPUT_FILE`  | `golden_set.json`                      | Golden question set          |
| `OUTPUT_FILE` | `baseline_results.csv`                 | Where results are written    |

## Limitations

- Keyword scoring only checks whether certain words appear. It does not judge whether the answer is correct, so a wrong answer can score well and a correct paraphrase can score poorly.
- Use the `Expected_Answer` column to manually review entries marked `REVIEW`.
- The average score is calculated only over successfully answered questions, and failed requests are reported separately.

## Next Steps

- Re-run with other models or prompts and compare against this v0.1 baseline.
- Add semantic scoring (for example embedding similarity or an LLM judge) alongside keyword coverage.
- Bump the `Release` value in `main.py` for each new run so results stay comparable.
